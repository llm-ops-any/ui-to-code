# 初始化自检清单

> 新项目第一次跑 AIDLC 时，**初始化收尾必过**。逐条打勾，缺一条就补一条，全过才说「初始化完成」。
> 为什么要有它：模板是「整份复制 + 填空」，但 agent 常把「复制」执行成「照意思重写一份精简版」——
> 文件都在，内容瘦了一半，谁也没发现（2026-10-26，hld-hj-web 实测）。

**机器能查的部分**：

```
python 开发文档/04技能/aidlc/scripts/自检.py
```

第 14 项「规则文件」查 `团队配置.md` 的档位名 / 五档清单 / 含义表 / 测试三档 / 人编号。
下面这些人眼过 —— 脚本查不出的语义问题。

---

## 1. `开发文档/00规则/项目概述.md`

来源：`references/项目概述.template.md` **整份复制**。

| # | 必含 | 判据 |
|---|---|---|
| 1 | 一句话定位 | 能说清「是什么、给谁用、解决什么问题」，不堆形容词 |
| 2 | 交付物形态 | 网页 / 服务 / 库 / 命令行；怎么访问、是否对外 |
| 3 | 技术栈与版本 | **写死版本号**（不写「最新」），并注明「以锁文件为准」 |
| 4 | 运行时拓扑 | 进程 / 容器表：谁对外、谁调谁、启几个 |
| 5 | 目录地图 | 入口在哪 / 业务逻辑写哪 / 哪个目录不许手改 |
| 6 | 核心链路 | ≥2 条端到端「入口 → 经过哪层 → 落到哪」，排错全靠它 |
| 7 | 外部依赖 | **只写服务名与用途，不写凭证值**；配错会怎样 |
| 8 | 硬约束 | 每条带理由，写「不看就白干一天」的坑 |
| 9 | 入场阅读顺序 | 先读什么、后读什么 |

**禁止**：写进度、待办、CR 列表、谁负责什么。

> 为什么：这些内容各归其位（进度 → `CR-XXXX/状态.md`，视图 → `_汇总/`，角色 → `团队配置.md`）。
> 概述里一旦混进进度，**它一周后就过期**，然后整份文件没人再信——包括其中真正稳定的那部分骨架。
> 概述的价值在「稳定」，不在「全」。

## 2. `开发文档/00规则/团队配置.md`

来源：`references/team-profile.template.md` **整份复制**。

| # | 必含 | 判据 |
|---|---|---|
| 1 | `## 项目` 段 | 项目名 / 仓库 / 产物命名 / **审批模式** / **测试策略** / 启用扩展 六项齐 |
| 2 | 审批模式行 | 档位名 ∈ 五档**且**行尾保留「五档可选：…」全清单 |
| 3 | `## 审批模式（五选一）` 整表 | 五档各一行，**含未被选中的四档** |
| 4 | 测试策略行 + 三档表 | 同样保留「三档可选：…」，不是只写当前档 |
| 5 | `## 角色` 表 | 列含「**人编号**」；一个 email 一行；多人共用账号的例外写清 |
| 6 | `## 当前身份怎么判定` | 三条以上：查 email / 匹配不到就问 / 切角色显式说明 / `AIDLC_PERSON` 覆盖 |
| 7 | `## 门禁与流转方式` | **按档位改**：`仅需求审批` 要把 G2/G3 标「本模式不生效」；`全自动` 写「无门禁」 |
| 8 | `## 例外与约定` | 本项目跳过哪些阶段、哪些不走门禁 |
| 9 | 构建命令（有则写） | `- 构建命令：…` —— 钩子靠它自动重建产物 |

**常见退化成精简版的样子**：审批模式写成「`关键三关`　←　G1 / G2 / G3 三处停」一句话（五档没了）；
删掉「四眼原则」段；删掉测试策略的「降档必须留痕」；门禁表照抄模板三关、档位却是仅需求审批。

## 3. `开发文档/00规则/开发规范.md`

来源：`references/dev-conventions.template.md` **整份复制**，只填技术栈相关的三四条
（语言/语法版本、交付形态、测试框架、目录是否分层）。

- [ ] 技术栈与版本写死（不写「最新」）
- [ ] 交付形态（单文件 / 打包 / 服务）
- [ ] 测试框架与放哪（没有就写「无自动化测试」+ 理由）
- [ ] 目录分层与命名（含哪些目录不许手改）

## 4. `开发文档/00规则/文档结构.md`

来源：本 SKILL.md 第 E 节的布局，**不许自创第二套**。

- [ ] 完整目录树（含 CR 目录内 14 类文件，不是只写「CR 目录自包含」一句）
- [ ] 「三步判定」：规则 → `00规则/`；属某条 CR → `<类型目录>/CR-XXXX/`；跨 CR 视图 → `汇总.py` 生成
- [ ] 「生成物 / 不入库」表（`_汇总/` 整目录、哪些视图）
- [ ] 「本项目补充」：额外目录、哪些文件是生成物、哪些历史资料只读不改

## 5. `开发文档/00规则/协作规范.md`（条件项）

- 单人作业 ⇒ **可以不建**，但要在 `文档结构.md` 写明「暂不建 + 为什么 + 什么时候补」
- 多人并行 ⇒ 从 `references/common/parallel-collaboration.md` 派生，**只写本项目差异**
  （分支策略、谁和谁并行、取号与合入顺序），不整份抄规则原文

## 6. 项目根锚点与目录

- [ ] `AGENTS.md` 含 `AIDLC:v2` 标记段（`install-project-anchors.py --with-skill` 一次搞定）
- [ ] `开发文档/01需求` `02缺陷` `03技术债` 三个类型目录已建
- [ ] `00规则/` 下四份必建规则文件齐全（项目概述 / 团队配置 / 开发规范 / 文档结构）
- [ ] `_汇总/` 已在 `.gitignore` 里，且**没有**被 git 跟踪
- [ ] 技能副本在 `开发文档/04技能/aidlc/`（项目要自包含时）

## 7. 收尾

- [ ] 跑一次 `自检.py`，无 ✗
- [ ] 播报里写清：审批模式 = 哪一档、测试策略 = 哪一档、跳过了哪些阶段及原因
- [ ] 自检结果记进首条 CR 的 `状态.md`（一句话 + 日期即可）

## 反例（2026-10-26 真实产出，别再来一次）

```markdown
- **审批模式**：`关键三关`　←　G1 需求定稿 / G2 设计定稿 / G3 代码合入三处停下等批准
```

三个问题叠在一起：① 五档可选清单没了，用户不知道还有 `仅需求审批`；
② 改成 `仅需求审批` 后这行注释没跟着改，**档位说不停、注释说停**；
③ 与下方门禁表的三关冲突，读到的人无法判断到底停几次。
