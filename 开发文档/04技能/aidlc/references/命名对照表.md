# 产物命名对照表（中文）

**本表是产物命名的唯一权威。** 规则文件（`references/` 下）里出现的英文路径，一律按本表映射；
新建任何文件或目录前，先查这里，**不要**照抄规则原文里的英文名。

> **布局只有一套**：`00规则 / 01需求 / 02缺陷 / 03技术债 / 04技能` + `_汇总`。
> 类型目录直接挂在 `开发文档/` 下，编号 01/02/03 定死顺序，不再套容器目录。

## 一、总览

```text
开发文档/
├── 00规则/                项目概述.md   团队配置.md   协作规范.md   开发规范.md   文档结构.md
├── 01需求/                CR-<8位号>-<简称>/   ← 需求：用户能感知的新行为（停 G1）
├── 02缺陷/                CR-<8位号>-<简称>/   ← 缺陷：与已批准预期不符（不停 G1）
├── 03技术债/              CR-<8位号>-<简称>/   ← 技术债：只改内部实现（停 G1）
│                          三类结构相同，只有门禁和主文档不同
│                          （需求=需求.md / 缺陷=问题.md / 技术债=变更说明.md）
│                          需求.md  状态.md
│                          设计/（应用设计 / 代码结构 / 工作单元 / 功能设计 / 非功能设计）
│                          测试记录.md  构建说明.md  验收报告.md  问题.md
│                          运维说明.md  变更说明.md  审计-<人>.md
│                          决策记录.md  前置资源.md  风险.md  证据/
├── 04技能/aidlc/          技能副本（含 scripts/；项目不自带副本时省略）
└── _汇总/                 ⚙ 9 个视图（本地生成·不入库）
```

⚙ = 由 `scripts/汇总.py` 生成，**不要手改、不要入库**（`.gitignore` 排除）。
**入库的只有分片**：`<类型目录>/CR-XXXX/*`（含 `审计-<人>.md`）—— 一条 CR 一个目录，两人各写各的，不冲突。

## 二、一个文件该放哪：三步判定

按顺序问，第一个「是」就停：

| # | 问题 | 去处 |
|---|---|---|
| 1 | 它是**规则/共识**吗？（团队配置、协作约定、目录结构、开发规范） | `00规则/` |
| 2 | 它**只属于某一条 CR** 吗？（需求、设计、测试记录、验收、问题、运维、审计） | `<类型目录>/CR-XXXX-<简称>/` |
| 3 | 它**跨多条 CR** 吗？（进度、索引、决策台账、审计流水） | **不手写**，跑 `汇总.py` 生成到 `_汇总/` |

**没有第四步。** 跨 CR 的东西一律是「算出来的视图」，不是「人工维护的文档」。

**最容易放错的两类**

- **基线需求**（v1.0 那批）→ `01需求/CR-00-初始版本/`，不是 `00规则/`。
- **设计** → 只进该 CR 的 `设计/`，**没有全局设计目录**。

## 三、根目录与控制文件

| 英文（规则文件里） | 中文（实际落盘） |
|---|---|
| `aidlc-docs/` | `开发文档/` |
| `aidlc-docs/aidlc-state.md` | `开发文档/状态.md`（每轮续跑读它） |
| `aidlc-docs/team-profile.md` | `开发文档/00规则/团队配置.md` |

| 布局与落点约定 | `开发文档/00规则/文档结构.md`（骨架见 `references/文档结构.template.md`） |

## 四、CR 区（01需求 / 02缺陷 / 03技术债）

| 英文 | 中文 |
|---|---|
| `inception/` | `01需求/CR-XXXX-<简称>/`；缺陷进 `02缺陷/`、技术债进 `03技术债/` |
| 取号 | `<类型目录>/CR-<8位号>-<简称>/`（**目录名就是号**：人1 + 年末位1 + 月日2 + 当日序号2，例 `CR-16102100-导出CSV/`） |
| 基线需求（v1.0 那批） | `01需求/CR-00-初始版本/`，`需求.md` 头部标 `- 需求性质：基线` |

## 六、测试与构建

**长期有效的测试方法**（怎么测、测什么）、**某一轮的运行结果**（跑了多少、过了多少、未覆盖什么）——
两者都跟着 CR 走，不再有独立测试目录。

| 英文 | 中文 |
|---|---|
| `construction/build-and-test/` | `CR-XXXX/测试记录.md` |
| `.../build-instructions.md` | `CR-XXXX/构建说明.md` |
| `.../unit-test-instructions.md` | `CR-XXXX/测试记录.md`（单元测试段） |
| `.../integration-test-instructions.md` | `CR-XXXX/测试记录.md`（集成测试段） |
| `.../performance-test-instructions.md` | `CR-XXXX/测试记录.md`（性能测试段） |
| `.../contract-test-instructions.md` | `CR-XXXX/测试记录.md`（契约测试段） |
| `.../security-test-instructions.md` | `CR-XXXX/测试记录.md`（安全测试段） |
| `.../e2e-test-instructions.md` | `CR-XXXX/测试记录.md`（端到端测试段） |

> 「静态检查做了什么、人工自测走了哪些路径、未覆盖什么」，**不得宣称「测试通过」**。

## 七、运维

| 英文 | 中文 |
|---|---|
| `operations/operations.md` | `CR-XXXX/运维说明.md`（只有部署/上线类 CR 才有） |

## 八、审计

| 英文 | 中文 |
|---|---|
| `aidlc-docs/audit.md` | `<类型目录>/CR-XXXX/审计-<人>.md`（一人一份） |
| 跨 CR 的条目（配置变更、结构变更、合并） | 仍写进发起它的那条 CR 的 `审计-<人>.md` |
| 合并视图（按时间倒序） | `_汇总/审计视图.md`（⚙ 本地生成·不入库） |

**一人一份，只追加**。两个人往同一个文件末尾追加照样冲突 —— git 看到的是「同一位置两段新增」。
分片是唯一能真正消除审计冲突的做法。

## 九、单元名怎么取

`{单元}` 用**业务名**，不用英文标识符：

- ✅ `工时统计`、`登录鉴权`、`任务列表`
- ❌ `timesheet-api`、`auth-module`、`todolist`

单元名会变成目录名，中文目录一眼能认出是什么业务；英文 slug 只在跨服务对接时才有价值，
那种情况在单元文档内部注明技术标识即可。

## 十、五条命名约定（吃过亏才写的）

1. **一眼看懂，不用猜**。`00-基线` 改成 `CR-00-初始版本`、全局 `设计/` 改成每条 CR 自己的 `CR-XXXX/设计/`，
   都是因为「看得懂」比「简洁」重要。
2. **抽象词必须加限定**。单说「设计」会被理解成美术设计；单说「基线」没人知道指哪批需求。
3. **目录带序号**（`00规则` → `04技能`），否则编辑器按字符排序，顺序不可预期。
   `_汇总` 用下划线开头，排在所有编号目录之后。
4. **一个概念一个名字**。同一个东西不要同时叫「需求增量 / 需求」「基线 / 初始版本」。
5. **改名要同步引用**：`开发文档/` 内所有路径引用、`AGENTS.md`、技能副本、`.gitattributes`、
   `core.hooksPath` 一起改。审计只增不减，历史条目不回改。

## 十一、项目根文件：不走中文命名（例外）

以下文件**必须保持英文名**，因为它们是跨工具约定，改名就失效：

| 文件 | 为什么必须英文 | 内容来源 |
|---|---|---|
| `AGENTS.md` | Codex / Claude Code / CodeBuddy 等工具进目录会先读这个名字。改成 `协作说明.md` 就没人读了 | `references/project-agents.template.md`（启动时复制，带 `AIDLC:v2` 标记） |
| `CLAUDE.md` | Claude Code 及其兼容工具的项目入口 | 同上（默认只放指针；`--full` 时放全文） |
| `开发文档/04技能/aidlc/` | 项目自包含的技能副本。目录名 `aidlc` **固定**，上级固定 `开发文档/04技能/` | `scripts/install-project-anchors.py --with-skill`，**整目录入库** |

> 中文命名只适用于 `开发文档/` 内部。**根目录下的跨工具约定文件一律保留 ASCII 名。**
> 若用户项目里已有 `AGENTS.md`，按其原文保留、只在末尾追加 AIDLC 段落，**不得覆盖或改名**。

## 十二、代码不受影响

中文命名只约束 `开发文档/` 下的文档，**代码文件的命名仍按各语言惯例**（`.js` / `.py` / `.ts` 等）。
不要把业务代码也改成中文文件名——那会破坏构建工具和 import 路径。
