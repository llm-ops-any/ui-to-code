# 开发规范

- 生效：2026-10-26
- 适用：本项目的全部代码与测试
- 性质：**项目级约定**。与 AIDLC 技能里的流程规则冲突时，流程以技能为准，代码风格以本文件为准。

> **怎么用**：本文件已按本项目（Next.js 15 + React 19 + TS 5 + Tailwind 4）填好；带 `<尖括号>` 的地方即本项目待定项。
> **写法原则：每条都写「为什么」。** 没有理由的规矩，下一个人遇到例外时没法判断该不该破。

---

## 一、语言与运行环境

| 规则 | 为什么 |
|---|---|
| TypeScript 5，`strict: true` 已开；不写 `any` 兜底（确实未知用 `unknown` 再收窄） | 现有代码全量 TS，一个 `any` 会让整条链路失去类型保护 |
| 交付形态：Next.js 全栈单体（App Router），`src/` 分层，构建产物交给 `next build` | 前后端同仓同进程，密钥才能只留在服务端 |
| 2 空格缩进、无分号、单引号（`page.tsx` / `hooks/` / `utils/` 现状一致） | 与既有代码一致，避免整文件格式化产生巨型 diff |
| 环境变量一律 `process.env.XXX` 直读；不要 `process.env?.XXX`（`process.env` 永不为空，`?.` 只是噪音） | 少一层无意义判断，且 reviewer 一眼看出有没有真判空 |
| 路径别名只用 `@/*`（映射 `./src/*`） | 已在 `tsconfig.json` 配好，相对路径跨层容易写错层级 |

> **不引外部依赖**（框架 / CDN / 字体 / 图标库）—— 要引先走变更请求，不在功能迭代里顺手加。

## 二、代码结构

- 分层：`app/`（路由与页面，只放路由和视图）→ `services/`（业务请求）→ `utils/`（传输层封装，如 SSE）→ `models/`（类型）；状态放 `hooks/`
- **`app/api/**` 只做桥接**：取 `process.env`、补鉴权头、按 `Content-Type` 分流、转发。任何拼装/加工逻辑放 `services/` 或 `hooks/`，否则这层会变成第二个后端
- **纯函数优先**：能写成纯函数的，不要塞进 UI 或状态层 —— 纯函数能直接测。
- **渲染只读**：渲染函数里不写状态、不调变更方法。
- **持久化单一出口**：所有写盘走同一处，换介质时才不会漏。
- **动作集中派发**：用户动作 → `dispatch({type})` → 状态方法，不在事件回调里直接改数据。

## 三、命名

| 对象 | 规则 |
|---|---|
| 文档、目录 | 中文 |
| 代码标识符 | 英文，小驼峰（`handleGenerateCode` / `useThrottle`）；组件用大驼峰 |
| 函数 | 动词开头（`parseXxx` / `applyXxx`） |
| 布尔 | `is` / `has` / `can` 开头 |
| 常量 | 全大写 + 下划线 |
| 测试挂点 | `data-testid`，kebab-case，**是契约不是装饰** |

**新增交互元素必须带 `data-testid`**，否则那段交互永远进不了自动化。

## 四、注释

- **引用需求编号**：`// CR-3 / FR-24：逐行校验，错误行不阻断其他行` —— 看代码能回查「为什么」。
- 写**为什么**，不写**是什么**。
- 用中文。
- **不留「临时」「先这样」和空 TODO**：要做就做，不做就进 CR。

## 五、可测性（写代码时就要想）

- 副作用集中且**可注入**（存储、下载、时钟）。
- 时间相关逻辑接受参数注入，不在函数内部直接取当前时间。
- 错误路径**明确返回值**（`{ok:false, error:'xxx'}`），不靠抛异常跨层传递。
- 访问宿主 API **包 try/catch，包括属性读取本身**（属性取值也可能抛）。

## 六、测试

- 框架：**暂无**（项目未引入测试框架，`团队配置.md` 测试策略为 `仅静态`）—— 要引入走 CR，不在功能迭代里顺手加。
  在引入之前，「验什么」写在 `验收报告.md` 的人工走查清单里，并注明未做自动化覆盖的风险。
- 用例名说清**验什么**，并标需求编号。
- 断言要**能证伪**：断言具体值，不断言「不为空」。
- 跑法写进测试文件头注释。
- 跑不跑由 `团队配置.md` 的**测试策略**决定（`全量` / `仅回归` / `仅静态`）。

## 七、提交

- 格式：`<type>(<CR号>): <中文摘要>`，如 `feat(CR-16102600): 上传失败弹具体错误`
- **一个提交一件事**：功能、文档同步、收尾补记录分开提。
- **不提交**可再生成物（构建产物、日志、截图）。
- 提交前跑一次汇总脚本 `--check`，生成物过期不要提交。
- 提交信息写清**已知缺口**（如「未跑自动化用例」）。

## 八、禁止事项

1. 不加外部依赖（要加走 CR）。
2. 不改已批准内容而不留痕。
3. 不覆盖审计（只追加；用户原话一字不改）。
4. 不把代码放进 `开发文档/`。
5. 不写死环境信息（IP、端口、路径）。
6. 不用 `innerHTML` 拼接用户输入。
7. 不为「看起来完整」造没人调用的代码。

## 九、例外怎么处理

任何一条要破，先说清三件事：① 破哪一条；② 为什么这里不适用；③ 破完的代价是什么。
三条都写进当轮审计。**不写就默认没破过。**
