# 项目概述

> 本文件是项目的「入场地图」：定位 / 交付形态 / 技术栈 / 运行时拓扑 / 目录地图 / 核心链路 / 外部依赖 / 硬约束。由人维护，agent 可提修改建议但不得自行扩写；**不写进度、待办、CR 列表**（进度在 CR，视图在 `_汇总/`）。

## 1. 一句话定位

上传一张 UI 截图，由 LLMOps 平台上的 Agent 生成 HTML 代码并在页面里实时预览的网页工具。

## 2. 交付物形态

- 形态：**网页**（Next.js 全栈单体，仅一个路由 `/`）
- 访问：本地 `npm run dev` → `http://localhost:3000`；生产 `next build` + `next start`
- 账号：**无登录、无用户体系**，会话靠 LLMOps 返回的 `end_user_id` / `conversation_id`
- 密钥：全部在服务端环境变量，浏览器只调本项目的 `/api/*`，不接触 COS 与 LLMOps 凭证

## 4. 运行时拓扑

| 组件 | 端口 | 职责 |
|---|---|---|
| 浏览器 | — | 选图、预览、代码展示；只与 Next.js 同源通信 |
| Next.js 应用（单进程） | 3000（dev） | 页面 + 两个 Route Handler：`/api/upload/image`、`/api/chat` |
| 腾讯云 COS | 443 | 存放上传的截图，返回公网 URL 供模型读取 |

> 唯一对外入口是 Next.js 应用；COS 与 LLMOps 只被服务端访问。

## 6. 核心链路

1. **图片上传**：`page.tsx` 选图 → `FileReader.readAsDataURL` 转 base64 → `POST /api/upload/image` → 服务端 `cos.putObject`（`uploads/<时间戳>.jpg`）→ 返回 `https://<bucket>.cos.<region>.myqcloud.com/uploads/xxx.jpg`
2. **代码生成（SSE）**：`handleGenerateCode` → `useChat.handleChat` → `services/chat` → `utils/request.ssePost` → `POST /api/chat`（服务端补 `app_id` + `Bearer <api_key>`）→ 转发 `${LLMOPS_API_BASE}/chat`，按 `Content-Type` 分 JSON / SSE / text 三路
3. **流式渲染**：前端逐事件解析 → 首帧取 `conversation_id` / `end_user_id` 存进 hook → 后续 `agent_message` 事件的 `answer` 累加进 `code` → `PreviewComponent` 用 `useThrottle(code, 200)` 节流写 `iframe.srcdoc`
4. **更新 / 重生成**：两者只差 query —— 「更新代码」把当前 `code` + 修改建议一起回传（`generateQuery`），「重新生成代码」从零重来；都复用同一 `conversation_id`

## 7. 外部依赖

> **只写服务名与用途，绝不写凭证值。** 凭证只放 `.env`（`复制 .env.example` 得到），不入库、不进 `开发文档/`。

| 依赖 | 用途 | 配错会怎样 |
|---|---|---|
| 腾讯云 COS（`COS_SECRET_ID` / `COS_SECRET_KEY` / `COS_REGION` / `COS_BUCKET`） | 存截图并给模型一个公网可读 URL | 上传 500，前端只弹「上传错误」，生成链路直接断在第一步 |
| LLMOps 开放 API（`LLMOPS_APP_ID` / `LLMOPS_API_KEY` / `LLMOPS_API_BASE`） | 截图 → 代码的 Agent | `/api/chat` 转发失败或返回非流式错误，页面一直停在「代码生成中…」 |
| 运行环境可访问外网 | 拉取 COS 图片、调用 LLMOps | 内网/断网时预览与生成全废 |

## 8. 硬约束（踩过的坑）

1. **密钥只能出现在服务端。** 只在 `src/app/api/**` 里读 `process.env`；**不要**给 `COS_*` / `LLMOPS_*` 加 `NEXT_PUBLIC_` 前缀 —— 加了就等于把密钥打进浏览器包。
2. **`/api/chat` 必须按 `Content-Type` 分流。** LLMOps 可能返回 JSON（出错）、`text/event-stream`（正常流）、纯 text 三种；只当流处理会在出错时静默卡死。
3. **图片必须先拿到公网 URL 才能进模型。** COS 上传是生成链路的前置条件，`generateQuery` 里的 `image_urls` 不接受 base64。
4. **`code` 是流式累加的，写 iframe 必须节流。** 直接 `iframe.srcdoc = code` 会每个 chunk 重建一次文档，页面卡死 —— 现有 `useThrottle(code, 200)` 不能去掉。
5. **`.env` 不入库。** `.gitignore` 用 `.env*` + `!.env.example`，新增变量必须同步补 `.env.example`。
6. **不顺手加依赖。** 当前 `package-lock.json` 与 `pnpm-lock.yaml` 并存已是隐患；要统一包管理器或引入测试框架，走 CR，不在功能迭代里顺手改。
7. **`next.config.ts` 的 `images.remotePatterns` 是 `hostname: '*'`。** 任意 https 图源都能过 `next/image`，属于已知放宽项，收紧需先确认 COS 域名。
