# CR-16102702 需求 · 容器化部署

- CR 号：`16102702`
- 需求性质：增量（部署方式变更）
- 提出人：张勇（PO）
- 登记时间：2026-10-27

## 1. 背景与目标

当前项目只有 `npm run dev` / `npm run build && npm start` 两种跑法，换机器就要重装 Node 与依赖。
PO 要求：**打成 Docker 服务，在本机部署跑起来**，且保留现有本地 dev 跑法。

**目标**

- 一条命令在本机起服务（`docker compose up -d --build`），浏览器 `http://localhost:3001` 可用
- 容器内仍能调 LLMOps 开放 API 与腾讯云 COS
- 镜像里**不含凭证**，凭证在运行时注入

**非目标**

- 不改业务逻辑、不加 npm 依赖、不引入数据库
- 不推镜像仓库、不做多环境（dev/prod 分镜像）、不做 HTTPS
- 不改动 `npm run dev` 的既有开发方式

## 2. 功能需求

| 编号 | 需求 |
|---|---|
| FR-01 | 多阶段 `Dockerfile`：`npm ci` 装依赖 → `next build` → 运行时只带 standalone 产物，镜像不含源码与 devDependencies |
| FR-02 | `.dockerignore` 排除 `node_modules`、`.next`、`.env*`、`开发文档`、`.git` |
| FR-03 | `docker-compose.yml`：端口映射可配（默认宿主 `3001` → 容器 `3000`），`env_file: .env` 注入凭证，配置 `host.docker.internal` 让容器访问宿主上的 LLMOps |
| FR-04 | `next.config.ts` 增加 `output: 'standalone'`（Next 15 官方容器化做法），否则运行时要带完整 `node_modules` |
| FR-05 | 容器内 `LLMOPS_API_BASE` 由 `http://localhost/api/openapi` 覆盖为 `http://host.docker.internal/api/openapi`（compose 里设，不改 `.env`） |

## 3. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-01 | 镜像不含任何密钥；`.env` 只经 `env_file` 在运行时注入 |
| NFR-02 | 构建可重复：`npm ci` 严格按 `package-lock.json` |
| NFR-03 | 容器 `restart: unless-stopped`，宿主重启后自动拉起 |
| NFR-04 | 不新增 npm 依赖（仅新增 Docker 相关文件） |

## 4. 验收标准

| 编号 | 场景 | 判据 |
|---|---|---|
| AC-01 | 构建 | `docker compose build` 成功，镜像大小合理（< 400MB） |
| AC-02 | 启动与访问 | `docker compose up -d` 后 `curl -I http://localhost:3001/` 返回 200 |
| AC-03 | 对话链路 | 容器内 `/api/chat` 转发成功，返回 SSE 且有回答 |
| AC-04 | 上传链路 | 容器内 `/api/upload/image` 能写 COS，返回 `image_url` |
| AC-05 | 凭证隔离 | `docker run --rm <image> ls -a /app` 看不到 `.env` |
| AC-06 | 重启存活 | `docker compose restart` 后再次访问 200 |

## 5. 数据影响与回滚

- **数据影响**：无。无数据库、无本地持久化；截图仍直传 COS（不落容器磁盘）。
- **回滚**：`docker compose down` 停服；`git revert` 撤销 Dockerfile/compose；本地 `npm run dev` 随时可回到原方式。
- **端口**：默认 `3001`（避开 dev 的 `3000`），冲突时改 `APP_PORT`。
